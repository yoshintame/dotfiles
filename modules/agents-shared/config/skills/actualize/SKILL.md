## Дельта поверх /extract

`/actualize` — maintenance-сессия содержимого: находит расхождения зафиксированного с реальностью и с самим собой и разрешает их. Вход — скоуп (таска, док, регион) плюс внешние сигналы: отчёт `/state-reconstruction` (недоведённая работа), implemented-таски, прямое указание пользователя. Применяй весь пайплайн и гарды `/extract`; ниже — только дельта.

1. **Сначала quiesce.** Если по скоупу есть подозрение на недоведённую работу (регион давно без коммитов, брошенные сессии) — прогони `/state-reconstruction` и дай пользователю дозакрыть сессии до актуализации: сканить и чинить недоведённые доки бессмысленно, актуализация по неполной картине закрепляет устаревшее.
2. **Источник истины — реальность, не план и не сам док**: implemented ≠ done, зафиксированное ≠ правда. Реальность читай сам: код, конфиги, git включая WIP, git-diff сделанной работы, timeline задач.
3. **Детекция по ходу чтения.** Читай скоуп целиком; границу держи по связям, не по папке. Два канала inline:
   - **дрейф** — сверяй current-state доки с системами, которые они описывают: код, конфиги, git;
   - **противоречия** — от правки или находки иди по связям волной: к связанным докам, от них к их связанным, пока новые не перестанут противоречить; волна может уйти за исходный скоуп — иди за ней. Только current-state и knowledge доки: противоречия внутри analysis / idea — история мысли, норма.
4. **Роутинг каждой находки по причине:**
   - устарело или изначально ошибочно зафиксировано → сверь с реальностью и почини сам;
   - реальность не читается агентом (реальный мир, намерения, приоритеты) → вопрос пользователю «какой вариант правильный?» — собери батч, не спрашивай по одному;
   - непродуманность: изменение внесли, влияние на другую часть системы упустили → доку не «чини» — противоречие честно отражает дыру в дизайне; зафиксируй open-question / task.
5. **Скоуп «одна таска» (implemented → done).** Реконструируй результат из git-diff и timeline. Догони спеки по `kind`: feature → business- и implementation-spec; bugfix → implementation (код вернулся к неизменной business-spec); refactor → только implementation. Genesis (current = ∅): выпусти под-доки spec-draft (`target-business` / `target-implementation`) в самостоятельные спеки, сверенные с кодом, под-доки удали, analysis заморозь `concluded`; значимый разрыв «замысел vs реальность» → decision. Заморозь task → `done` целиком (коммиты, acceptance, timeline — не расплющивай). Закрой разрешённые open-question: `resolved` / `dropped`.
6. **Структурные ходы — по желанию, не по обязанности.** Напрашивающийся по ходу починки ход (расщепить, перенести, ретипизировать) делай; полная пересборка раскладки региона — не твоя ноша, это `/rewrite`.
7. **Хвост — в task.** Каскад, который сессия не вывозит (правке противоречит больше корпуса, чем влезает в контекст), зафиксируй как task с перечнем оставшегося — не тяни обязательные цепочки сессий.
8. **Финал.** Обычный финал `/extract` (проверка, линтеры, коммит шагами). Если дальше планируется `/rewrite` региона — `/handoff-create` с дистиллятом: какие ошибки сняты, какие противоречия в чью пользу решены, диапазон коммитов — детали ссылкой на коммиты, не пересказом.
