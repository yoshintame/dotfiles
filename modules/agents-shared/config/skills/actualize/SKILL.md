## Задача

Актуализировать указанный скоуп документации — таску, док, регион, связку доков фичи: найти все несоответствия действительности, все внутренние ошибки и противоречия — и разрешить их.

Источник истины — реальность, которую читаешь сам: код, конфиги, git включая WIP, timeline задач. Не план и не сами доки: план описывает намерение, с которым реализация разъехалась, а доки — то, что ты проверяешь, ими нельзя подтверждать их же правоту.

## База: /extract обязателен

Этот скил — дельта поверх `/extract`. Если `/extract` ещё не загружен в контекст сессии — вызови его через Skill tool **прямо сейчас, до любых действий**: пайплайн записи, гарды и таблица роутинга живут там.

## План

1. **Подними недоведённую работу.** Git и код не покажут правду, висящую в брошенных сессиях. Когда скоуп широкий или регион давно без коммитов (полная актуализация региона — почти всегда) — прогони `/state-reconstruction`, дай пользователю дозакрыть сессии и только потом правь: актуализация по неполной картине закрепляет устаревшее. При точечном скоупе с уверенным «WIP нет» от пользователя — пропусти шаг.
2. **Прочитай скоуп целиком, находи расхождения по ходу.** Границу держи по связям, не по папке. Два способа поиска, одновременно:
   - **дрейф** — сверяй current-state доки с системами, которые они описывают: код, конфиги, git;
   - **противоречия** — от каждой находки иди по связям волной: к связанным докам, от них к их связанным, пока новые не перестанут противоречить; волна может уйти за исходный скоуп — иди за ней. Проверяй только current-state и knowledge доки: противоречия внутри analysis / idea — история мысли, норма.
3. **Разрешай каждую находку по её причине:**
   - устарело или изначально ошибочно зафиксировано → сверь с реальностью и почини сам;
   - реальность агенту не читается (реальный мир, намерения, приоритеты) → вопрос пользователю «какой вариант правильный?» — собери батч, не спрашивай по одному;
   - непродуманность (изменение внесли, влияние на другую часть системы упустили) → доку не «чини»: противоречие честно отражает дыру в дизайне — зафиксируй open-question / task.
4. **Скоуп «implemented-таска» — доведи цикл до done.** Реконструируй результат из git-diff и timeline. Догони спеки по `kind`: feature → business- и implementation-spec; bugfix → implementation (код вернулся к неизменной business-spec); refactor → только implementation. Genesis (current = ∅): выпусти под-доки spec-draft (`target-business` / `target-implementation`) в самостоятельные спеки, сверенные с кодом, под-доки удали, analysis заморозь `concluded`; значимый разрыв «замысел vs реальность» → decision. Заморозь task → `done` целиком (коммиты, acceptance, timeline — не расплющивай). Закрой разрешённые open-question: `resolved` / `dropped`.
5. **Структурные ходы — по желанию, не по обязанности.** Напрашивающийся по ходу починки ход (расщепить, перенести, ретипизировать) делай; полная пересборка раскладки региона — не твоя ноша, это `/rewrite`.
6. **Не вывозишь каскад — хвост в task.** Когда правке противоречит больше корпуса, чем влезает в контекст, зафиксируй оставшееся как task с перечнем — не тяни обязательные цепочки сессий.
7. **Финал.** Обычный финал `/extract`: проверка, линтеры, коммит шагами. Если дальше планируется `/rewrite` региона — `/handoff-create` с дистиллятом: какие ошибки сняты, какие противоречия в чью пользу решены, диапазон коммитов — детали ссылкой на коммиты, не пересказом.
