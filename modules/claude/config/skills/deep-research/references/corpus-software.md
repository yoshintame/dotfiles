# Корпус: софт

Для дискавери софта три источника — три разных ключа над одним множеством инструментов, и у двух из трёх сломан retrieval:

| Источник | Индексируется по | Отказ |
|---|---|---|
| GitHub | авторские `name`/`description` — словарь того, кто инструмент уже знает | циркулярно: чтобы найти, надо знать слова автора |
| Reddit / HN | **анонс** — автор объясняет инструмент чужим, то есть словарь ищущего | ранжирование Reddit антикоррелирует (ниже); HN в порядке |

Выкинуть любой из трёх — дыра. Кураторские индексы (awesome-списки) бьют все три — майнить первыми.

Вызовы: `search-github` **всегда с `dangerouslyDisableSandbox: true`** — под сандбоксом он умирает с `tls: failed to verify certificate: x509: OSStatus -26276`, и ошибка читается как обычный сбой команды. Тред целиком — `search-reddit fetch <url>` / `search-hn fetch <id>`, не WebFetch: вывод чище.

## Awesome-майнинг — три шага, первым делом

```bash
search-github awesome "<capability>"     # шаг 1, ракурс возможности: «semantic search»
search-github awesome "<ecosystem>"      # шаг 1, ракурс экосистемы: «claude-code», «obsidian»
gh api repos/<owner>/<repo>/contents/README.md --jq .content | base64 -d   # шаг 2: прочитать README списка
search-github search "<query>"           # шаг 3: прямой поиск, добивка после майнинга
```

Шаг 2 — то, ради чего всё: найти awesome-список — не значит прочитать его; список, найденный шагом 1 и не прочитанный, — несделанный шаг. README читай целиком, семантически: лексика автора списка расходится с твоей, и греп по ключевым словам промахивается так же, как буквальный поиск GitHub, — а проход глазами ловит кандидата, описанного чужими словами. Греп (`… | rg -i '<name>'`) оставь для одного случая: проверить, есть ли в списке уже известное имя.

Шаг 3 буквален: `search-github search` матчит `name`/`description`, то есть попадает, только когда запрос почти цитирует слова автора. Поэтому прогони ≥3 разных формулировки того, как автор мог назвать или описать инструмент, а пустую выдачу трактуй как ничего не доказывающую — главным каналом дискавери этот шаг быть не может. Звёздные фильтры (`--stars ">30"`) молча режут хвост, где живут новые инструменты, — во время дискавери не ставь.

Отсюда же правило резолва: **имя, взятое из анонса, ищи через `fetch` самого анонса**, а не поиском по имени. URL репозитория почти всегда в теле поста — `search-reddit fetch <url>` / `search-hn fetch <id>` сначала, `search-github search` потом. Пустой поиск по имени, которое ты прочитал в анонсе, доказывает лишь то, что описание автора звучит иначе.

Тот же порядок в ветке «есть ли известный баг»: issue-трекер репозитория и changelog — первичный источник, `search-reddit`/`search-hn` добирают обсуждения, которых в трекере нет.

## Reddit: сортировка решает

- **Дискавери → `--sort new`.** Анонсы живут на 0–12 баллах, а `relevance` и `top` скор-взвешены и ранжируют против них: на скор-взвешенной сортировке выдача заполняется обсуждениями, а инструментов в ней нет. Сканируй заголовки, скором не фильтруй — низкий балл у анонса нормален.
- **Настроения и migration stories → `relevance` или `top`** — там высокий скор и есть сигнал.

```bash
search-reddit search "built" --sub <subreddit> --sort new --time year --limit 25
```

Запросы держи в 2 слова; длиннее — только вместе с `--sub`, иначе выдачу забивают вирусные посты со случайным совпадением. Причина механическая: многословный запрос скрипт превращает в Lucene `+word1 +word2`, то есть требует все слова разом. Пустая выдача на длинном запросе — повод повторить с `--loose` или укоротить, а не вывод об отсутствии. Синтаксис Reddit проходит насквозь: `title:X author:Y` работает.

## HN

Ценность HN — не аудитория и не комментарии, а работающий поиск Algolia по заголовкам и текстам анонсов. Запускай его, даже когда тема кажется не-HN-ной: анонс инструмента попадает туда независимо от того, «профильная» ли для HN область.

```bash
search-hn search "<query>" --tags show_hn   # анонсы и запуски
search-hn search "<query>" --by-date        # хронологически: свежий инцидент, релиз, разбор
```

## Красные флаги кандидата

Заброшенность, смена лицензии, единственный мейнтейнер, отставание релизов от кода, рост цены, треды «ушли с него на …».

Первые четыре снимаются одной командой — прогоняй её по каждому финалисту, а не читай карточку репозитория глазами:

```bash
search-github health <owner/repo>
```

Ещё один канал дискавери мимо поиска — `search-github trending <topic>`: ранжирует по звёздам в день, поэтому показывает молодое и растущее, которое по абсолютным звёздам ещё невидимо.
