## Дельта поверх /extract

`reconcile` — стадия 3 (раскладка) reconcile-пайплайна из трёх сессий: `/state-reconstruction` (стадия 1) поднял незафиксированное, `/actualize-region` (стадия 2) выправил содержимое по месту. Формула пайплайна: **прочитай всё, что зафиксировано** по региону → **актуализируй это знание** → **сними старую фиксацию** → **выполни `/extract`** над полученным знанием как над незафиксированным выводом сессии; эта стадия исполняет две последние стрелки. Догнать одну спеку по ходу — `/actualize-spec`. Применяй весь пайплайн и гарды `/extract`; ниже — только дельта.

1. **Входы обязательны.** Handoff с дистиллятами стадий 1–2. Без них раскладку не начинай — отошли к началу пайплайна (`/state-reconstruction` → `/actualize-region`): холодный вызов схлопывает три фокуса в одну сессию, и ни один не выживает.
2. **Инвариант доверия.** Содержимое корпуса правильно и актуально — это гарантия стадии 2; ошибок не ищи, вся ёмкость контекста уходит на структуру. Дистиллят стадии 2 держи при переписывании: какие ошибки сняты, какие противоречия в чью пользу решены — rewrite по памяти легко регенерирует то, что стадия 2 только что вычистила.
3. **Широкий обзор структуры.** Прочитай регион целиком; границу держи по связям, не по папке. Ищи структурную деградацию: конфляция ролей (один док = несколько ролей), отсутствующие типы (сущность погребена в теле другого дока), рваность от точечных правок, разбухание (**>500 строк**).
4. **План реструктуризации** — одним сообщением, два обязательных блока; дождись подтверждения перед перетряской:
   - **(а) Целевая раскладка** — дерево файлов/папок по типам и ролям, спроектированное так, как если бы знания региона **нигде не были зафиксированы** и раскладывались с нуля.
   - **(б) Вердикт каждому старому файлу**: `удалить` / `остаётся домом` / `переехать в <путь>`. Файлов региона без вердикта в плане нет.
5. **Исполнение плана.** Целевые доки пиши с нуля чистыми снимками (старые — источник фактов, не черновик); уникальный unit сначала приземли в целевой дом, затем источник **удали** по вердикту — git хранит всё, а страх сноса старого — главный режим отказа reconcile. Расщепление свалки, ретипизация, выпуск погребённых сущностей (Гард 3), переписывание начисто (Гард 4) — частные случаи метода; бэклинки удалённых — де-линкуй или перенацель.
6. **Сверка с планом.** Пройди план шага 4 построчно: каждый вердикт исполнен буквально, каждый целевой док существует и несёт своё знание; отклонение — либо явно обоснуй, либо доделай. FM1-линтер по затронутому; коммить шагами, не одним комом. Следующей стадии нет — handoff не создаётся.
