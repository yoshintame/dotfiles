## Дельта поверх /extract

`/actualize` — сессия резолюции maintenance-находок: берёт расхождения — отчёты каналов детекции (`/audit`, `/state-reconstruction`, implemented-таска) или прямое указание пользователя — и приводит корпус к реальности. Применяй весь пайплайн и гарды `/extract`; ниже — только дельта.

1. **Источник истины — реальность, не план и не сам док**: implemented ≠ done, зафиксированное ≠ правда. Реальность читай сам: код, конфиги, git включая WIP, git-diff сделанной работы, timeline задач.
2. **Роутинг каждой находки по причине:**
   - устарело или изначально ошибочно зафиксировано → сверь с реальностью и почини сам;
   - реальность не читается агентом (реальный мир, намерения, приоритеты) → вопрос пользователю «какой вариант правильный?» — собери батч, не спрашивай по одному;
   - непродуманность: изменение внесли, влияние на другую часть системы упустили → доку не «чини» — противоречие честно отражает дыру в дизайне; зафиксируй open-question / task;
   - противоречия внутри analysis / idea — не находки: история мысли, норма.
3. **Скоуп «одна таска» (implemented → done).** Реконструируй результат из git-diff и timeline. Догони спеки по `kind`: feature → business- и implementation-spec; bugfix → implementation (код вернулся к неизменной business-spec); refactor → только implementation. Genesis (current = ∅): выпусти под-доки spec-draft (`target-business` / `target-implementation`) в самостоятельные спеки, сверенные с кодом, под-доки удали, analysis заморозь `concluded`; значимый разрыв «замысел vs реальность» → decision. Заморозь task → `done` целиком (коммиты, acceptance, timeline — не расплющивай). Закрой разрешённые open-question: `resolved` / `dropped`.
4. **Структурные ходы запрещены.** Не переноси, не переименовывай, не меняй `type:`, не расщепляй и не сливай доки — раскладка принадлежит `/rewrite`. Гард 4 — только внутри файла (переписать начисто на месте); кандидатов на расщепление помечай в дистилляте.
5. **Хвост — в task.** Каскад, который сессия не вывозит (правке противоречит больше корпуса, чем влезает в контекст), зафиксируй как task с перечнем оставшегося — не тяни обязательные цепочки сессий.
6. **Финал.** Обычный финал `/extract` (проверка, линтеры, коммит шагами). Если дальше планируется `/rewrite` региона — `/handoff-create` с дистиллятом: какие ошибки сняты, какие противоречия в чью пользу решены, кандидаты на расщепление, диапазон коммитов — детали ссылкой на коммиты, не пересказом.
