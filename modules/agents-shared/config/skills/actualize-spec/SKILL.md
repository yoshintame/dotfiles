description: Догоняет current-state спеку до реально сделанной работы.
---

`actualize-spec` = `/extract` + переход `implemented → done`. Применяй весь пайплан и гарды `/extract` (роутинг, FM1-линтер, пропорция/альтитуда, одна-роль, переписать-начисто) — ниже только дельта, гарды не повторяю. Узкий, по ходу: догнать **одну** спеку до сделанного в рамках обычного цикла; широкая реструктуризация региона — это `/reconcile`.

Источник истины — **результат, а не план**: `implemented ≠ done`. В ходе реализации многое разъезжается с замыслом; спеки догоняются из того, что реально в проде.

## Дельта поверх /extract

1. **Реконструируй реальный результат.** Прочитай git-diff сделанной работы (что реально зашипилось) и `timeline` задачи — не только план. Что изменилось против замысла — узнаёшь отсюда.
2. **Догони спеки из результата.** Перепиши затронутые current-state доки под реальность, на месте, чистым снимком: `business-spec` (новое/изменённое поведение домена), `implementation-spec` (как реально построено). Какую догонять — по `kind` задачи: `feature` → обе; `bugfix` → код вернулся к неизменной `business-spec`, правится разве что `implementation-spec`; `refactor` → только `implementation-spec`. Никогда «было → стало» (Гард 1).
3. **Genesis (current = ∅).** Если работа реализовала forward-дизайн (`analysis kind:spec-draft` с под-доками `target-business` / `target-implementation`) — **выпусти** под-доки в самостоятельные `business-spec` / `implementation-spec`, сверенные с кодом, и удали под-доки. `analysis` заморозь `concluded`, оставив только груминг (то, что спека не дублирует) со ссылками на выпущенные спеки. Дубля target↔spec не оставляй; значимый разрыв «замысел vs реальность» → `decision`.
4. **Заморозь task.** Статус → `done` по конвенции контекста. Сохрани целиком (коммиты, acceptance, `timeline`) — не удаляй, не расплющивай в хронику.
5. **Закрой open-question**, которые работа разрешила: `resolved` (ответ ушёл в спеку / `decision`) или `dropped`. Устаревший снимок / решённый вопрос — удалить (история в git).

Дальше — обычные шаги `/extract`: проверка (FM1-линтер по правленым спекам) и коммит.
