## Задача

Актуализировать указанный скоуп документации (таску, док, регион, связку доков фичи): найти все несоответствия действительности, все внутренние ошибки и противоречия, и разрешить их.

Источник истины всегда реальность, которую читаешь сам: код, конфиги, git включая WIP, timeline задач. Замыслу не доверяй как описанию сделанного: ТЗ задачи, roadmap, target-под-доки genesis описывают намерение, с которым реализация разъехалась (implemented ≠ done). Самим current-state докам тоже: они предмет проверки, ими нельзя подтверждать их же правоту.

## База: /extract обязателен

Этот скил только дельта поверх `/extract`. Если `/extract` ещё не загружен в контекст сессии, вызови его через Skill tool **прямо сейчас, до любых действий**: пайплайн записи, гарды и таблица роутинга живут там.

## Шаги

1. **Подними недоведённую работу.** Git и код не покажут правду, висящую в брошенных сессиях. Когда скоуп широкий или регион давно без коммитов (полная актуализация региона подпадает почти всегда), прогони `/state-reconstruction`, дай пользователю дозакрыть сессии и только потом иди дальше: детекция по неполной картине даёт ложные находки, а починка закрепляет устаревшее. Пропускай шаг только при точечном скоупе с уверенным «WIP нет» от пользователя.
2. **Эксплоринг в plan mode.** Сам вызови `EnterPlanMode` и веди детекцию read-only, ничего не правя. Читай скоуп целиком; границу держи по связям, а не по папке. Ищи двумя способами одновременно:
   - **дрейф**: сверяй current-state доки с системами, которые они описывают (код, конфиги, git);
   - **противоречия**: от каждой находки иди по связям волной, к связанным докам, от них к их связанным, пока новые не перестанут противоречить; волна может уйти за исходный скоуп, иди за ней. Находки фиксируй только по current-state и knowledge докам: они претендуют на «как есть», устаревание в них дефект. Analysis / idea читай как контекст, но разделяй два случая: внутренняя разведка (взвешенные варианты, отвергнутый путь) это история мысли, не находка; фактическое устаревание находка и в них, особенно в active analysis (process-артефакт, не снапшот), но предлагаемая резолюция там lifecycle-ход, а не правка текста: analysis актуализировать / завершить concluded / выпустить в spec или decision, у idea сдвинуть статус, тело не трогать.
3. **План находок на апрув.** Выйди через `ExitPlanMode`; план это список находок чекбоксами, по строке на находку: `- [ ] док: что не так, диагноз, предлагаемая резолюция`. Вопросы, чей ответ лежит вне досягаемости агента (физический мир, намерения, приоритеты), включи в план явными развилками с вариантами: план и есть батч вопросов пользователю, по одному не спрашивай. Пользователь правит план и апрувит. Если скоуп большой и исполнять будет другая сессия, после апрува заверши сессию через `/handoff-create` со ссылкой на план-файл (`~/.claude/plans/*.md`) в must-read: fix-сессия стартует чистой и читает только затронутые доки.
4. **Исполняй по плану, отмечая чекбоксы.** Резолюция каждой находки предложена планом и апрувнута; типовые ходы:
   - устарело или изначально ошибочно зафиксировано: сверь с реальностью и почини сам;
   - развилка из плана: исполняй выбранный пользователем вариант; новые вопросы по ходу собирай батчем, а не спрашивай по одному;
   - непродуманность (изменение внесли, а влияние на другую часть системы упустили): доку не «чини», противоречие честно отражает дыру в дизайне; зафиксируй open-question / task;
   - lifecycle-ход для analysis / idea: статус, заморозка, выпуск; рассуждения не переписывай.
   Закрытую находку отмечай в план-файле: `- [x]`.
5. **Скоуп «implemented-таска»: доведи цикл до done.** Реконструируй результат из git-diff и timeline. Догони спеки по `kind`: feature затрагивает business- и implementation-spec; bugfix только implementation (код вернулся к неизменной business-spec); refactor только implementation. Genesis (current = ∅): выпусти под-доки spec-draft (`target-business` / `target-implementation`) в самостоятельные спеки, сверенные с кодом, под-доки удали, analysis заморозь `concluded`; значимый разрыв замысла с реальностью зафиксируй как decision. Заморозь task в `done` целиком (коммиты, acceptance, timeline не расплющивай). Закрой разрешённые open-question: `resolved` / `dropped`.
6. **Структурные ходы делай по желанию, обязанности нет.** Напрашивающийся по ходу починки ход (расщепить, перенести, ретипизировать) делай; полная пересборка раскладки региона не твоя ноша, это `/rewrite`.
7. **Сверка и финал.** Пройди чекбоксы плана построчно: каждый закрыт или явно отложен с причиной. Дальше обычный финал `/extract`: проверка, линтеры, коммит шагами. Если дальше планируется `/rewrite` региона, заверши через `/handoff-create` с дистиллятом: какие ошибки сняты, какие противоречия в чью пользу решены, диапазон коммитов; детали давай ссылкой на коммиты, а не пересказом.
