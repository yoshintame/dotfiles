Движок актуализации: разложить вывод сессии по типизированным артефактам, переписать current-state доки под реальность, закоммитить. Агностичен к контексту — конкретный surface (какой `type:`, какая папка, как заведён документ) берётся из конвенций контекста, а не зашит здесь.

## Процедура

1. **Прочитай конвенции контекста.** Вызови conventions-скил этого хранилища — `/obsidian-vault`, `/senate-vault` или docs-скил репо. Он даёт surface: как роль кодируется в `type:`/папку, где лежит тип, как создаётся/мутируется документ (CRUD-тулинг, если есть; иначе пишешь файл по конвенции — frontmatter, kebab-slug, папка типа, даты не угадывай, бери из системы). Детект контекста (senate / личный vault / dev-репо) выводи из сессии.
2. **Классифицируй** вывод сессии на units. У каждого — одна роль (см. таблицу). Роль определяет тип.
3. **Роутинг.** Каждый unit → тип по таблице. Это и есть Гард 3: декомпозируй разнородное по ролям, не сваливай в один док.
4. **Применяй.** НЕ append. Перечитай целевой док целиком, переосмысли, перепиши на месте чистым current-state-снимком (create / update по конвенции). Перенос между доками — явный шаг.
5. **Гарды** (ниже) — на каждой записи в current-state док.
6. **Проверь.** Записанное читается само по себе, без контекста сессии. Wikilinks резолвятся. Прогнал FM1-линтер.
7. **Коммит** — вшит финальным шагом: `git-commit-atomic -C <repo> --auto -S "<msg>" <правленые файлы>` (позиционно — не загребай чужое dirty).

## Таблица роутинга (роль → тип)

| Вывод сессии | Тип |
|---|---|
| Что система делает сейчас (домен, intent) | переписать в **business-spec** на месте |
| Как система построена сейчас (код / инфра) | переписать в **implementation-spec** на месте |
| Подлинный разворот / отвергнутая альтернатива + причина | **decision** |
| Origin-story (весь путь, почему так пришли) | **analysis** (`concluded`) |
| Нерешённость (развилка / неизвестность / нужен вход) | **open-question** |
| Предложение «надо бы X» | **idea** (если не прорабатывается сразу) |
| План / шаги | **task** |
| Хроника (что, когда сделано) | `timeline:` соответствующей `task` (отдельного лога нет) |
| Решённый open-Q / устаревший снимок | **удалить** (история в git) |
| Сама завершённая работа | **заморозить** (`done` / `concluded`) — не удалять, не расплющивать |

`decision` оправдан только когда несёт контекст **за рамками финальной спеки** (разворот / отвергнутая альтернатива с причиной). Просто констатация финального дизайна — это спека, её место в спеке. Surface (точное имя `type:`, папка, доп. типы инстанса) — из конвенций контекста.

## Гарды

Срабатывают при правке любого **current-state** дока (`business-spec` / `implementation-spec`). Распознать роль дока — обязательный первый шаг: иначе Гард 1 либо пропустит историю в спеке, либо снесёт законную хронику в process-доке.

**Гард 1 — нет истории в спеке.** Спека — «что ЕСТЬ», без временной шкалы. Разворотный язык — баг: `раньше`, `прежн…`, `было ошибкой`, `пересмотрено`, `убрано`, разворотное `теперь`, `было X стало Y`. Дельту и её причину разноси (таблица), не держи в спеке. После правки:

```
bun ~/.claude/skills/extract/scripts/history-lint.ts <правленый файл или папка>
```

Маркеры детерминированы; линтер пропускает history-роли (`analysis`/`task`/`idea`/`open-question`/`decision`/`incident`) и fenced-код. Доверяй; вычищай каждое срабатывание в current-state доке.

**Гард 2 — пропорция и альтитуда.** Масштаб правки соразмеряй со значимостью изменения **для всей системы**, а не с тем, сколько места оно заняло в чате. Перекос систематичен в одну сторону: раздуваешь то, чем забит контекст, — чаще ошибка в том, что мелкое изменение разбухает до полдока; но по-настоящему крупное заслуживает крупной правки. Альтитуда: правка вливается на той же высоте детализации, что окружающий док (без UI-подписей и пошаговости в высокоуровневом доке). Новый раздел — только под новое *понятие*, не под реализацию. Не задетые разделы не трогай.

**Гард 3 — один артефакт, одна роль.** = таблица роутинга выше. Не сваливай разнородное в спеку — декомпозируй по ролям и разнеси.

**Гард 4 — переписывай начисто, не латай.** Несколько точечных правок подряд (особенно разными сессиями) рвут файл: структура уходит, копятся повторы и нестыковки. Как только видишь, что файл дошёл до этого, — бросай латание, прочитай целиком, перепиши как один связный снимок (это переоформление, не добавление объёма — Гард 2 держится). Единственное исключение из «не задетые разделы не трогай». Если файл накопил несколько разъезжающихся концернов (признак — **>500 строк**) — разбей на доки по ролям/темам, не переписывай в один разбухший.
